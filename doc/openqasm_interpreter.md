# OpenQASM 3.0 Interpreter

The `OpenQASMInterpreter` provides a complete execution environment for OpenQASM 3.0 programs within the QartVM ecosystem. It allows you to parse, analyze, and simulate quantum circuits defined using the OpenQASM 3.0 language.

## Overview

The interpreter works by executing the Abstract Syntax Tree (AST) generated by the `OpenQASMParser`. It maintains an execution context that tracks:
- **Quantum Memory**: Qubits and their states.
- **Classical Memory**: Classical variables (integers, arrays, bitsets).
- **Gate Definitions**: Custom gates defined in the program.
- **Subroutines**: User-defined subroutines.

## Usage

To use the interpreter, you need to parse your OpenQASM code first and then pass the resulting `Program` object to the `execute` method.

### Basic Example

```dart
import 'package:qartvm/src/openqasm/openqasm_parser.dart';
import 'package:qartvm/src/openqasm/openqasm_interpreter.dart';
import 'package:qartvm/src/openqasm/interpreter/openqasm_include_provider.dart';

void main() async {
  final code = '''
    OPENQASM 3.0;
    include "stdgates.inc";
    
    qubit[2] q;
    bit[2] c;
    
    h q[0];
    cx q[0], q[1];
    
    c = measure q;
  ''';

  // 1. Parse the program (parser availability assumed)
  final program = OpenQASMParser.parse(code);

  // 2. Create the interpreter
  // You can optionally provide an include provider for loading files
  final interpreter = OpenQASMInterpreter(
    includeProvider: DefaultIncludeProvider(), 
  );

  // 3. Execute
  final result = await interpreter.execute(program);

  // 4. Inspect results
  print('Measurements: ${result.measurements}');
  print('Classical Variables: ${result.classicalVariables}');
  
  if (result.quantumMemory != null) {
     print('Quantum State Probabilities: ${result.quantumMemory!.probabilities}');
  }
}
```

## Supported Features

### Language Constructs
The interpreter supports a wide range of OpenQASM 3.0 features:

*   **Variable Declarations**:
    *   `qubit` types (single and arrays).
    *   Classical types (`bit`, `int`, etc.) with initialization.
    *   `constants`.
*   **Control Flow**:
    *   `if` / `else` branchin.
    *   `for` loops (range-based and collection-based).
    *   `while` loops.
    *   `break` and `continue`.
*   **Operations**:
    *   **Gate Calls**: Applying built-in and custom gates.
    *   **Measurement**: Measuring qubits into classical bits.
    *   **Reset**: Resetting qubits to the |0> state.
    *   **Assignment**: Assigning values to classical variables (including compound operators like `+=`, `^=`, etc.).
*   **Definitions**:
    *   `gate` definitions (defining new unitary gates).
    *   `def` subroutines.

### Standard Gate Library (`stdgates.inc`)
When `include "stdgates.inc";` is used, the interpreter registers efficient native implementations for standard gates:

**Single-Qubit Gates:**
*   `id` (Identity)
*   `h` (Hadamard)
*   `x`, `y`, `z` (Pauli matrices)
*   `s`, `sdg` (Phase S and S†)
*   `t`, `tdg` (Phase T and T†)
*   `sx` (Square root of X)

**Parameterized Single-Qubit Gates:**
*   `rx(θ)`, `ry(θ)`, `rz(θ)` (Rotations)
*   `p(λ)` / `phase(λ)` (Phase shift)
*   `u1`, `u2`, `u3` (General unitary)

**Multi-Qubit Gates:**
*   `cx` / `CX` / `cnot` (Controlled-NOT)
*   `cy`, `cz` (Controlled-Y, Controlled-Z)
*   `cp` / `cphase` (Controlled-Phase)
*   `crx`, `cry`, `crz` (Controlled Rotations)
*   `ch` (Controlled-Hadamard)
*   `swap` (Swap)
*   `ccx` (Toffoli / Controlled-Controlled-NOT)
*   `cswap` (Fredkin / Controlled-Swap)

### Conformance & Limitations

The interpreter targets **OpenQASM 3.x**.

*   **Unsupported Features**:
    *   `extern` declarations are currently ignored (no-op).
    *   `input` / `output` IO statements are ignored (no-op).
    *   `alias` statements are not yet implemented.
    *   Complex timing constraints or hardware-specific directives are ignored as this is a functional simulator.

## Architecture

The interpreter uses a **Quantum Memory Model** (`QMemorySpace`) to simulate the state vector of the system.
*   **Pre-scan**: The interpreter performs an initial pass to determine the total number of qubits required by the program to allocate the state vector efficiently.
*   **Async Execution**: Execution is asynchronous (`Future<InterpreterResult>`) to support asynchronous loading of included files (e.g., over a network or file system) and asynchronous observers.
*   **Expression Evaluation**: A robust `ExpressionEvaluator` handles complex arithmetic and boolean expressions for gate parameters and control flow conditions.

## Program Observers

The interpreter supports an observer pattern that allows you to monitor program execution step-by-step. This is useful for debugging, visualization, or analyzing the quantum state evolution.

### Adding an Observer

You can register an observer using the `addObserver` method. The observer callback is invoked before each statement is executed (except for `include` statements which are handled successfully).

The callback provides:
1.  **Step Count**: The current step number (0-indexed).
2.  **Statement**: The `Statement` object about to be executed.
3.  **Quantum Memory View**: A read-only view (`QMemorySpaceView`) of the current quantum state.

```dart
// Define an observer
final observer = (int step, Statement stmt, QMemorySpaceView qmem) {
  print('Step $step: Executing ${stmt.runtimeType}');
  
  // Inspect quantum state (read-only)
  print('Probabilities: ${qmem.probabilities}');
  print('Amplitudes: ${qmem.amplitudes}');
};

// Register the observer
interpreter.addObserver(observer);

// Execute the program
await interpreter.execute(program);
```

### Async Observers

Observers can be asynchronous. If your observer callback returns a `Future`, the interpreter will await it before proceeding to the next step. This allows for side effects like I/O or pausing execution without blocking the main thread.

```dart
interpreter.addObserver((step, stmt, qmem) async {
  // Simulate a delay or wait for user input
  await Future.delayed(Duration(milliseconds: 100));
  print('Step $step complete');
});
```

### Security (Read-Only Access)

To ensure the integrity of the simulation, observers are provided with a `QMemorySpaceView`. This interface allows inspection of the quantum state (size, amplitudes, probabilities) but prevents any modification to the state vector. This ensures that observers cannot inadvertently alter the program's execution logic.
